# 0011. 팀 저장소에도 파일 변경은 확인 후 PR 로 올리고, 푸시할 수 없으면 패치로 물러난다

- 상태: 승인 (2026-09-22)

## 맥락

[0005](0005-team-repos-propose-only.md) 는 팀 저장소의 공유 자산을 고치지 않고 제안만 하게 했다. 그런데
PR 은 병합되기 전까지 기본 브랜치에 영향이 없고, 팀이 리뷰해서 받을지 정한다. 제안을 말로만 남기면 팀원이
그 내용을 다시 옮겨 적어야 하지만, PR 이면 리뷰한 뒤 그대로 받을 수 있다(2026-09-22 사용자 확인).

반면 GitHub 설정(보안 기능, 브랜치 보호)은 PR 로 올릴 수 없고 바꾸는 즉시 팀 전체에 적용된다. 또 팀
저장소에서는 권한이 읽기뿐이거나, 브랜치 이름 규칙·서명된 커밋·푸시 제한 같은 정책 때문에 푸시가 거절될 수
있다.

## 결정

팀 저장소에서도 파일 변경은 확인을 받은 뒤 세팅 PR 로 올린다. 0005 는 승인 상태로 두고, 그 가운데 파일
변경에 관한 부분만 이 결정이 좁힌다. GitHub 설정은 여전히 바꾸지 않고 계획만 보인다.

푸시할 수 없으면 제안으로 물러난다. 저장소 권한이 `READ` 나 `TRIAGE` 면 푸시를 시도하지 않고, 푸시가
거절되면 거절 메시지를 그대로 보고한다. 두 경우 모두 로컬 브랜치와 커밋을 남기고 `git format-patch` 로 만든
패치 파일의 경로를 알려 준다. 포크해서 올리지 않는다.

## 결과

- 팀은 제안을 리뷰해서 그대로 받을 수 있다. 병합 여부는 여전히 팀이 정한다.
- 팀 저장소에 PR 이 생기고, 그 PR 에서 팀의 워크플로가 돈다. 비공개 저장소라면 조직의 Actions 사용량을
  쓴다. 푸시 직전 카드가 이 사실과 리뷰 요청이 갈 사람을 보인다.
- 라이선스처럼 회사가 정할 값이 들어가는 파일은, 팀이 정한 값을 사용자가 알려 줄 때만 만든다.
- 푸시할 수 없는 저장소에서도 사람이 쓸 수 있는 결과(패치 파일)가 남는다.
- 이 계정에는 조직이 없어 실제 조직 저장소에서 확인하지 않았다. 팀 저장소의 판별과 패치로 물러나는 흐름은
  아직 실제로 돌려 보지 않았다.
